## 2. How the software works

| Step | Status | Where |
|---|---|---|

| A person checks after comparing | done | `api/approvals.rs::check_recommendation` |
| Comparison table shown to the factory | done | `GET …/recommendations/{id}` returns every compared quotation; `RecommendationPanel.tsx` → `ComparisonTable` |
| The factory decides supplier and price | done | factory approvers only (`domain/workflow.rs`, `api/approvals.rs`) |
| 4. After approval, the AI sends the order email | **was missing → done** | `api/order_email.rs`: prepared from the approved quotation and the factory's PO number; our staff tick the check and send; goes through the outbox (test mode unless live mail is configured); one per order (migration 0022); automatic `send_order` task; `OrderEmail.tsx` |

## Questions for the CEO

1. **The order email names the factory** (the supplier must deliver to it and invoice it). Quote
   requests still do not name it. Is that right?
2. **Delivery address**: the order email uses the request's delivery location. Should a fixed
   factory address and contact person be stored once instead?
3. **No reply**: the task opens after the end of the response date (or 72 hours after sending
   without a date). Is that the right moment?
4. **Monthly invoice**: it bills every unbilled fee for orders placed up to the end of the month
   (an order reconciled late is billed the next month). Correct?

Open questions 2–5 and 7 of `FACTORY_SIDE_MODEL.md` (36 months per item or per contract, new
items, shipping, when to invoice) stay at their defaults; question 7 is now answered by the CEO
(we send the order email).
